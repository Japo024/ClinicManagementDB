# Clinic Management Database

A robust, relational database schema built in MS SQL Server for managing clinic and hospital operations. This project provides a complete structural foundation for tracking medical specialties, healthcare professionals, patient records, and appointment scheduling, alongside built-in auditing and error-handling mechanisms.

## Database Schema

The `ClinicManagementDB` consists of the following core tables:

*   **Specialties:** Stores clinical departments (e.g., Cardiology, Neurology), their floor locations, and monthly budgets.
*   **Doctors:** Contains doctor profiles, license numbers, consultation fees, and links them to their respective specialties.
*   **Patients:** Manages patient demographics, unique 11-digit personal IDs, dates of birth, and blood types.
*   **Appointments:** Handles scheduling between patients and doctors, tracking dates, times, status (Scheduled, Completed, Cancelled, NoShow), and clinical notes.
*   **SystemAuditLogs:** Automatically tracks historical changes (e.g., status updates) made to critical records.
*   **ErrorLogs:** Captures system and transaction errors generated by stored procedures for administrative review.

## Key Features

### Data Integrity & Constraints
*   **Unique Scheduling:** Prevents double-booking by ensuring a doctor cannot have two appointments scheduled at the exact same time.
*   **Format Validation:** Enforces strict 11-character limits for Patient IDs and validates blood type entries.
*   **Cascading Actions:** Deleting a patient or doctor automatically cascades to remove their associated appointments, maintaining database cleanliness.

### Programmatic Objects
*   **Views (`v_Upcoming_Appointments`):** Provides a clean, consolidated report of all active, upcoming appointments including patient names, doctor names, and specialty details.
*   **Triggers (`trg_AppointmentStatus_Update`):** Automatically captures any changes to an appointment's status and logs the old and new values, along with the user who made the change, into the `SystemAuditLogs` table.
*   **Stored Procedures (`usp_BackupClinicDatabase`):** Executes a full database backup with compression. It utilizes a `TRY...CATCH` block to automatically write any runtime errors to the `ErrorLogs` table without crashing silently.

### Security & Role-Based Access Control (RBAC)
*   **`clinic_admin`:** Granted full database ownership capabilities.
*   **`front_desk_receptionist`:** Tailored permissions allowing receptionists to view (`SELECT`), add (`INSERT`), and modify (`UPDATE`) patient and appointment data, while strictly denying the ability to delete (`DELETE`) records.

## Prerequisites
*   Microsoft SQL Server (2016 or newer recommended)
*   SQL Server Management Studio (SSMS), Azure Data Studio, or VS Code with the MSSQL extension.

## Usage Instructions

1.  Clone this repository to your local machine.
2.  Open the `init.sql` file in your preferred SQL client.
3.  Connect to your local or remote SQL Server instance.
4.  Execute the script. The script will automatically:
    *   Create the `ClinicManagementDB` database.
    *   Generate all tables, constraints, and indexes.
    *   Insert sample data (in Georgian) for testing purposes.
    *   Create the views, triggers, stored procedures, and user roles.
5.  To view the upcoming appointments, run: 
    ```sql
    SELECT * FROM v_Upcoming_Appointments;
    ```
